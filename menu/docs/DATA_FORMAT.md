# 数据格式规范

本文件是**唯一权威格式定义**。整条链路：

```
食谱截图 / 公众号文章
    ↓ ① AI 解析
中间 JSON（schema_version=1，可留档可弃）
    ↓ ② 写入
腾讯文档智能表格（唯一真相，手机可改）
    ↓ ③ 每天 09:50 读取
QQ 群消息（当日午餐 + 当日晚餐 + 次日早餐）
```

---

## ① 中间 JSON

```json
{
  "schema_version": 1,
  "week_start": "2026-10-19",
  "week_end": "2026-10-23",
  "source": {"type": "image", "title": "第8周食谱", "ref": "menu/inbox/第8周.png"},
  "parsed_at": "2026-10-18T20:03:11",
  "days": [
    {
      "date": "2026-10-19",
      "weekday": "周一",
      "meals": {
        "早餐": ["小米粥", "水煮蛋", "牛奶"],
        "午餐": ["米饭", "红烧肉", "清炒油麦菜", "紫菜蛋花汤"],
        "晚餐": ["米饭", "番茄鸡蛋", "冬瓜汤"]
      }
    }
  ]
}
```

| 字段 | 必填 | 规则 |
|---|---|---|
| `schema_version` | 是 | 固定 `1` |
| `week_start` / `week_end` | 是 | `YYYY-MM-DD` |
| `days` | 是 | ≥1 项，按 `date` 升序 |
| `days[].date` | 是 | `YYYY-MM-DD`，**唯一键** |
| `days[].weekday` | 否 | `周一`…`周日`，缺省由 date 推算 |
| `days[].meals` | 是 | key 属于 `早餐/午餐/晚餐/加餐`，value 为菜名数组 |

**餐次说明**：表格只有 `早餐/午餐/晚餐` 三列。AI 即使解析出 `加餐`，也不会写进表格、
不会发到群里 —— 留着只为了不丢信息（万一以后要加回来）。

**菜名数组**：一道菜一个元素。不要写 `"米饭+红烧肉"` 这种合并项。

## ② 腾讯文档智能表格

建一张**智能表格（Smartsheet）**，子表命名 `食谱`。列名**逐字一致**，全部选「文本」类型：

| 列名 | 必需 | 示例 | 说明 |
|---|---|---|---|
| `日期` | ✅ | `2026-10-19` | **唯一键**，程序靠它 upsert 和查当天 |
| `星期` | ✅ | `周一` | |
| `早餐` | ✅ | `小米粥、水煮蛋、牛奶` | 次日早餐会发 |
| `午餐` | ✅ | `米饭、红烧肉、紫菜蛋花汤` | 当天发 |
| `晚餐` | ✅ | `米饭、番茄鸡蛋` | 当天发 |
| `更新时间` | 可选 | `2026-10-18 20:03` | 表里有才写，用于判断数据新旧 |

**没有「加餐」「备注」列**，程序不会写它们。表里如果已经建了，留着无害（程序自动跳过）。

### 为什么一行一天

QQ 每天发一条消息，一行一天与一条消息天然对齐；一周 5~6 行，手机上划两下看完。
如果做成「日期|餐次|菜品」窄表，一周 15 行，肉眼核对更累。

### 周日也要录

学校发的是整周食谱（周一到周日）。寄宿制周日有晚餐（返校第一顿），**这一行必须录**，
否则周五那条消息没法预告周日晚餐。周五的晚餐通常没有——那不是漏录，是离校日。

规则统一为：**表里有内容就录，空白格跳过**。周六一般全空，不录。

### 为什么日期用文本

智能表格的日期类型底层存毫秒时间戳，读写都要转换。时区处理稍有不慎就出现
「写 26 号、读出来 25 号」，这种错极难排查。文本 `2026-10-19` 零歧义，
字符串排序也等于时间顺序。

### 多道菜分隔

单元格内用顿号 `、` 分隔。菜名本身带顿号（极少）写入时自动换成逗号 `，`，
否则读回来会拆错。

### ⚠️ 排列顺序 = 语义契约

顿号拼接会把表格的**行标签**（主食/大荤/小荤/素菜/汤）丢掉，而「哪道是主打」
正是靠行标签判断的。所以顺序必须由提取端固化，规则如下：

**午餐 / 晚餐**，按此优先级排列（主角永远第一位）：

| 位次 | 内容 | 判断依据 |
|---|---|---|
| 1 | **主角** | ① 大荤行第一道菜 ② 无大荤行时，主食行是拌面/刀削面/水饺/炒饭这类 → 取它 ③ 都没有 → 取第一个明显主菜（肉/蛋/鱼/鸡）；连这个都没有就**不设主角** |
| 之后 | 大荤 → 小荤 → 素菜 → 汤 → 主食 → 粥 | 按原表行序 |

**早餐**：不设主角，保持 `主食 → 杂粮 → 小菜 → 鸡蛋 → 粥` 原表顺序。

示例（对齐上表真实数据）：

```
原图           午餐：主食 馒头 | 大荤 大盘鸡拌面 | 素菜 白灼青菜 | 汤 鸡蛋面汤
写入单元格      大盘鸡拌面、白灼青菜、鸡蛋面汤、馒头
                ↑ 大荤行的拌面提到首位        ↑ 馒头后置
```

```
原图           午餐：主食 米饭 | 大荤 红烧肉 | 小荤 西红柿炒鸡蛋 | 素菜 蒜香青菜 | 汤 鸡蛋醪糟汤
写入单元格      红烧肉、西红柿炒鸡蛋、蒜香青菜、鸡蛋醪糟汤、米饭
```

发送端拿到这个顺序后，只做三件确定性的事，**不做任何语义判断**：

1. 第一位 = 主角（兜底：若第一位不含 肉/鱼/蛋/面/饭 等字样，说明这餐确实没主菜，降级为平铺）
2. `馒头 / 花卷 / 蒸鸡蛋` 折叠进消息末尾「每日标配」
3. `米饭` 出现在标题里（`午餐｜米饭 + 红烧肉`），其余同理进 emoji 表查图标

所以**提取端排序错了，消息就难看**，但不会漏菜 —— 顺序只影响突出程度，不影响完整性。

### 列结构自动适配

`upsert_menu()` 先调「查询字段」接口拿真实列名，**只写存在的列**：

- 缺必需列 → 报错并列出缺哪几列
- 有 `更新时间` → 写；没有 → 跳过
- 表里有 `加餐`/`备注` → 不管它

所以你随时能在腾讯文档里增删列，不用改代码。

## ③ QQ 群消息

**发送内容固定为三块：当日午餐、当日晚餐、次日早餐。**

```
📣 今日食谱 · 10月26日 周一

🍱 午餐｜主打：大盘鸡拌面
　🥬 白灼青菜
　🥣 鸡蛋面汤

🌙 晚餐｜主打：木须肉片
　🥬 干锅花菜
　🥣 大米粥

—— 明日早餐 · 10月27日 周二 ——
　🍞 蒸肉卷
　🌽 玉米
　🥬 酸辣土豆丝
　🥛 奶香豆浆

💡 每日标配：馒头 · 蒸鸡蛋
```

米饭日的形态会自动变化 —— 主食进标题，配菜平铺：

```
🍱 午餐｜米饭 + 红烧肉
　🍅 西红柿炒鸡蛋
　🥬 蒜香青菜
　🥣 鸡蛋醪糟汤
```

规则：

| 情况 | 行为 |
|---|---|
| 当天有午餐/晚餐 | 正常发送 |
| 次日有早餐 | 附在最后，带 `—— 明日早餐 · X月X日 ——` 分隔 |
| 次日整天不在校（正常周五） | 往后找 **1~8 天内第一个有晚餐的日期**，附 `—— 周X晚餐 · 月日 ——`，并提示「今日没有晚餐（下午离校）」 |
| 当天只有早餐（如周六） | **什么都不发** |
| 当天完全没数据（假期） | **什么都不发** |
| 晚餐缺失 | 只发午餐，`🌙 晚餐` 整块省略 |
| 一餐全是馒头花卷 | 标题 + 「常规早餐」，不留空段 |
| **周日** | 只检查午餐。周日晚餐已在周五预告过，不再重复；周日无午餐（正常返校日）则**静默** |

### 寄宿制：周五要预告周日晚餐

学校是周日下午返校吃晚饭、周五下午离校，中间断档。周日晚餐不能等到周日才发
（那时按规则不发送），所以在周五那条里提前给出：

```
📣 今日食谱 · 10月23日 周五

🍱 午餐｜主打：酸汤水饺
　🥣 玉米面汤

🚌 今日没有晚餐（下午离校）

—— 周日晚餐 · 10月25日 ——
　🍖 肉片炒面筋
　🥬 芹菜炒花生
　🥣 红豆粥

💡 每日标配：馒头
```

判定方式是**数据驱动**，不认星期几，所以调休自动适配（`tests/test_resume.py` 覆盖了 6 种情形）：

| 情形 | 结果 |
|---|---|
| 正常周四 | 周五还有午餐 → 不触发，周五自己发 |
| 正常周五 | 周六整天没数据 → 找周日晚餐 ✅ |
| 调休：周六上课 | 周六有午餐 → 不触发，周五改附周六早餐 |
| 调休：周日不返校 | 往后都没有晚餐 → 不附 |
| 长假（隔 6 天） | 仍能找到 → 附假期后第一顿晚餐 |
| 周六半天（只有早餐） | 触发 → 找周日晚餐 |

所以周末和假期不需要手动关任务，自然会静默。

消息里不放链接（链接域名需在开放平台提前登记，否则整条发送失败）。

🍅 西红柿 · 🐟 鱼虾蟹 · 🥟 饺/馄饨/包子 · 🍞 面点（卷/饼/馍/发糕）· 🍚 米饭炒饭 ·
🥛 牛奶豆浆 · 🥣 粥汤羹 · 🍜 面条类 · 🥚 蛋 · 🍖 肉禽骨 · 🌽 玉米 · 🍠 薯类南瓜 ·
🥬 素菜豆制品 · 🍽 兜底

## 校验规则

`save_menu.py` 写库前会检查，不通过就中止（截图留在 inbox 可重跑）：

1. 所有日期是合法 `YYYY-MM-DD`，且 `days[].date` 无重复
2. 每个 `days[].meals` 非空，餐次名属于 `早餐/午餐/晚餐/加餐`
3. 每道菜是非空字符串
4. 菜名里不含 `、`（顿号是单元格分隔符，混进去会导致读回来拆错）
